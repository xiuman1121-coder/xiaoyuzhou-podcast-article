# 基于逐字稿的后续问答规则

## 适用范围

用于文章生成后的自然追问，例如：

- “Loop 是什么意思？”
- “他为什么认为 Benchmark 失效了？”
- “节目里的 8000 美元是怎么来的？”
- “这是主播的观点，还是节目引用的数据？”
- “这一点节目有没有给出反例？”

在同一对话中，默认使用最近完成的节目。新对话或存在多个候选节目时，根据用户给出的链接、标题或输出目录定位；仍无法唯一确定时再请用户指定。

## 取证顺序

1. 在 `article.json` 中找到相关章节和 Key Takeaway。
2. 用 `source-map.json` 定位对应时间与 segment。
3. 读取 `transcript.json` 中相关 segment，并向前、向后扩展足够上下文。
4. 用 Show Notes 校正专名、数据、图片含义和时间线，不打开普通外链。
5. 区分说话人的原始主张、节目引用的资料、Agent 的概括和外部补充。

不要只依赖最终 HTML。HTML 是整理结果，逐字稿才是问答的主要证据。

## 回答层级

### 播客中的回答

说明节目实际说了什么，给出一个或多个时间范围，例如 `[32:16–39:46]`。可以清理口头语，但直接引语必须能逐字核对。不要把主播引用的数据写成已经独立验证的事实；使用“节目引用的统计称”等准确表述。

### 换句话说

把原意改写成普通读者容易理解的语言，可以使用简短类比、步骤或小例子。若例子不是主播原例，明确说明它是通俗解释。解释不得改变原结论、删去限制条件或扩大适用范围。

### 补充说明（播客未提及）

逐字稿没有回答、只回答一部分，或者用户明确要求扩展时才使用。先写明节目没有涉及的边界，再给补充内容。对时效性、医疗、法律、金融等信息先核查可靠来源，并把来源与播客证据分开。

### 边界

出现以下情况时主动说明：

- 节目提出问题但没有给出答案；
- 说话人只表达个人判断；
- 引用数据未在节目中验证；
- 转写词语、数字或人物归属无法确认；
- Agent 使用了自己的类比或推论。

## 默认表达

优先给出直接答案，再按需要使用小标题。不要为了展示规则而机械输出空栏目。

当节目材料足够时：

```text
播客中的回答
节目原意和时间范围

换句话说
通俗解释

边界
必要的限制或未回答部分
```

当节目完全没有提及时：

```text
这期播客没有讨论这个问题。

补充说明（播客未提及）
简短回答，并按需要提供外部来源。
```

## 禁止事项

- 不根据文章标题或摘要猜测逐字稿内容。
- 不把通俗类比写成主播原话。
- 不把外部常识混进“播客中的回答”。
- 不因回答更完整而隐去节目中的不确定性、反例或分歧。
- 不自动修改已经交付的 HTML；用户明确要求补入文章时，重新执行来源审计。
