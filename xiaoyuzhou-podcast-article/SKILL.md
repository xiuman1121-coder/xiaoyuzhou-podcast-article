# 小宇宙播客阅读版

把小宇宙节目变成可以代替收听的文章。默认成品是本地 `index.html`；用户不必明确说“HTML”。

## 必须遵守

- 保留节目原始标题，不把疑问改成结论，也不擅自改变立场和语气。
- 只依据音频、可靠逐字稿和 Show Notes 本身整理。不得编造事实、数字、观点、因果或说话人。
- 无法确认时采用保守描述；影响核心含义的内容宁可标为待核对或省略，也不能猜。
- 外部图文版只可校正专名、术语、明确数字、原句和明显转录错误；不得借用其结构或补入音频没有的内容。
- Show Notes 中的其他外链默认不打开、不读取、不引用。只有用户明确要求时才处理。
- 默认关闭编辑补充、背景解释和观点扩展。
- 先按时间戳和话题分块整理，再做有限的全篇编排；不要把整篇逐字稿一次性改写。
- 内容检查失败时停止成文，保留已有材料并生成失败报告。不得用推测填补缺失段落。

## 工作流程

1. 运行 `scripts/fetch_episode.py`，提取原始标题、节目资料、Show Notes、音频地址和全部图片，并下载临时音频。
2. 优先检查页面中是否有可用字幕。字幕必须有连续时间戳并覆盖主体内容；否则运行 `scripts/transcribe.py`。
3. 默认使用本地 `faster-whisper` 的 `small` 模型；设备资源不足或 `small` 无法运行时改用 `base`。只支持这两个模型，不使用 MLX。无需 API Key。
4. 运行 `scripts/validate_transcript.py`。先人工核对标题、人物、术语、数字、时间覆盖和明显错听，再进入写作。
5. 阅读 [内容整理规则](references/editorial-rules.md)，逐段制作 `article.json`、`source-map.json` 与图片取舍记录。输入输出格式见 [数据格式](references/formats.md)。
6. 运行 `scripts/render_article.py` 生成固定样式的 `index.html`，再运行 `scripts/audit_package.py` 做交付检查。
7. 检查通过后运行 `scripts/cleanup_audio.py` 删除临时音频。若最终停止重试，也删除临时音频。

执行命令、目录规则、字幕判断和失败分支见 [运行流程](references/workflow.md)。遇到依赖、模型或转写问题时再读 [故障处理](references/troubleshooting.md)。

## 交付要求

默认输出到用户桌面的 `xiaoyuzhou-podcast-article/<单集名称>/`；可用参数改到其他位置。至少保留：

- `index.html`
- `transcript.txt`
- `transcript.json`
- `source-map.json`
- `image-decisions.json`
- `data-points.json`
- `content-profile.json`
- `argument-map.json`
- HTML 引用的 `assets/`

文章顺序固定为：标题与节目资料、导读、3–7 条互不重复的 Key Takeaways、按时间推进的正文、简短来源说明。阅读时间是信息完整后的结果，不是压缩目标；高密度或 PPT 驱动节目应自然增加篇幅或分篇。忠实、信息完整和原有推理链优先于固定字数。

生成后告诉用户成品路径、实际转写来源、采用的 Whisper 模型、是否存在待核对项，以及临时音频是否已删除。

内容整理由当前运行本 Skill 的 Agent 完成，不绑定特定厂商或固定模型。标点、分段和明显转录错误也在逐段核对时处理，不另起一个会脱离音频的自由改写阶段。

## 基于逐字稿的后续问答

文章完成后，用户继续询问节目中的概念、观点、数字、论据或人物表达时，读取本期的 `article.json`、`source-map.json` 和 `transcript.json` 回答。先定位文章相关章节，再回到对应时间段，并同时查看相邻片段，避免只根据文章摘要或单句回答。

回答要区分三类内容：

1. **播客中的回答**：忠实概括节目内容，并给出时间范围。
2. **换句话说**：用更容易理解的语言解释原意；明确这是 Agent 的通俗转述，不伪装成主播原话。
3. **补充说明（播客未提及）**：只有逐字稿不足以回答时才出现，并明确它来自一般知识或外部资料。

如果节目只回答了一部分，明确指出它说了什么、没有说什么。若问题完全未被节目讨论，先直接说明，再提供简短且有明确标签的补充答案。涉及可能变化的事实或高风险信息时，补充答案需要核查可靠来源。

不要机械展示所有标题：材料足够时通常使用“播客中的回答＋换句话说＋边界”；无需外部补充时明确省略。详细规则见 [后续问答规则](references/follow-up-qa.md)。除非用户明确要求，不把问答内容写回正式文章。
